1. 项目概述

1.1 项目背景

微邮付任务管理系统是一个综合性的商户任务管理平台，支持目标商户管理→正式商户管理→任务下发与执行的完整业务流程。 系统包含PC端管理平台和移动端执行应用，实现商户全生命周期的数字化管理。

项目子背景:

当前的客户经理任务管理功能以“任务类型”（如切换通道、合并补充资料、存量商户走访、目标商户走访等）为主要维度进行组织和展示。客户经理需要处理上级下发的各类任务。

现有模式痛点: - 效率低下: 当任务类型增多，或同一商户存在多个不同类型的任务时，客户经理需要在不同任务列表间频繁切换，查找不便，处理效率低。 - 不符合实际作业习惯: 客户经理线下走访商户时，更倾向于一次性处理完该商户的所有待办事项，现有模式无法很好地支持这种以商户为中心的作业方式。 - 扩展性受限: 未来新增任务类型，需要不断增加新的列表入口，导致功能臃肿，维护成本高。 - 外部协同: 需要更好地支持与外部系统（如邮付易推小程序）的数据联动和任务处理协同。
在实际业务运营过程中，商户经常会遇到风控和挂账问题：
- 风控主要包括微信、支付宝等支付渠道的风控，以及第三方支付通道的风控；
- 挂账则主要发生在第三方支付通道。
当前，平台在收到风控或挂账通知后，通常采用纯手工处理方式：平台首先通知各省运营，再进行分发至商户的客户经理，由客户经理协助商户准备相关资料，再由平台与上游通道方沟通处理。这一流程不仅耗时耗力，且缺乏标准化和系统化的管理，容易导致响应不及时、处理效率低下，影响商户的正常业务和满意度。随着风控和挂账场景的增多，现有的人工处理方式已难以满足业务发展的需求，急需建立一套高效、规范的风控挂账任务处理机制。
当前的目标商户走访功能，主要依赖机构在PC后台导入商户信息或客户经理自行拓展并手动录入。商户信息下发后，客户经理在移动端进行走访、打卡，并逐步将其转化为平台的正式商户。此模式下，商户的发现和覆盖范围有一定局限性。
为提升商户拓展效率和覆盖面，计划引入腾讯地图服务及其点位商户信息，并结合机构的区域化管理策略。这将使客户经理能通过地图直观发现潜在商户，机构也能通过地图进行更精细化的区域性战略部署和任务指派，同时逐步沉淀平台自有的商户数据资产。

核心业务场景:

  • 存量商户的任务下发与处理（补充资料、切换通道、走访维护、风控、挂账等）
  • 目标商户的拓展与转化（目标商户→意向商户→正式商户）
  • 基于腾讯地图的商户位置展示与POI信息管理
  • 机构层级化的任务下发与监控

1.2 项目目标

  • 提升客户经理工作效率
  • 扩大商户覆盖范围
  • 构建平台数据资产
  • 建立与规范风控挂账任务处理机制
  • 提升商户服务体验
  • 提高任务完成率
  • 实现商户转化率

3. 功能模块详解

3.1 PC端功能模块

正式商户管理

  • • 商户列表管理（筛选、排序、搜索）
  • • 任务统计概览（总数、完成率、状态分布）
  • • 批量任务导入（Excel模板）
  • • 任务详情查看（任务维度/商户维度）
  • • 任务类型：补充资料、切换通道、走访维护、风控、挂账

目标商户管理（基本原逻辑）

  • • 目标商户统计（目标/意向/正式商户数量）
  • • 来源管理（系统录入/手动上传）
  • • 地区分布统计（市/县/营业所维度）
  • • 商户进度跟踪
  • • 批量目标商户导入

地图功能

  • • 地图找商户：绘制区域获取腾讯POI潜客信息
  • • POI数据导出：将潜客信息导出为Excel
  • • 目标商户导入：将POI潜客手动导入为目标商户

任务驾驶舱 本期不做

  • • 实时数据监控（商户总数、任务总数）
  • • 可视化图表（饼图、趋势图、热力图）
  • • 动态交互（时间筛选、数字滚动）
  • • 异常预警（任务超时、完成率低）
  • • 决策支持（多维度数据分析）

3.2 移动端功能模块

任务管理

  • 任务类型选择页：存量商户/目标商户选择入口
  • 商户任务列表：待领取/已领取，进行中/已完成分段
  • 地图模式：商户位置可视化，地图与列表联动
  • 任务详情：任务状态分段，操作按钮，通知提醒
  • 商户领取：正式商户任务3天有效期，到期前提醒

目标商户拓展

  • 目标商户列表：不同来源商户展示和管理
  • 地图商户：目标商户地图展示，快速导航
  • 新增目标商户：表单填写，地址定位，照片上传
  • 商户转化：目标→意向→正式的状态流转
  • 打卡走访：工作量统计，转化记录

正式商户任务处理

  • 补充资料任务：商户信息完善，资料上传
  • 切换通道任务：通道变更确认，测试验证
  • 走访维护任务：实地走访，服务记录
  • 风控任务：风险调查，材料收集，分享链接
  • 挂账任务：解决方案选择，账户信息处理

商户详情

  • 目标商户详情：基础信息，打卡状态，业绩录入
  • 意向商户详情：进度跟踪，转化操作，备注管理
  • 正式商户关联：商户号输入，状态关联
  • 正式商户详情：查看正式商户详情
  • 正式商户任务详情：正式商户具体任务详情

3.3 核心业务规则

⚠️ 重要业务规则

  • • 商户领取后有3天处理时限，到期前1天自动提醒
  • • 客户经理领取商户后，该商户下所有任务都由其负责
  • • 目标商户转化流程：目标商户→意向商户→正式商户
  • • 地图功能：目标商户与正式商户位置展示，手动录入展示位置
  • • 目标商户来源：PC端系统导入、客户经理手动添加
业务场景 规则说明 异常处理
商户领取 3天有效期，期间需处理至少1个任务 到期自动释放，需重新领取
任务状态流转 待处理→审核中→已完成（或驳回→重新提交） 驳回时推送通知，支持重新提交
商户转化 状态变更后同网点客户经理可见 转化失败时提示具体原因
权限控制 按机构层级和地理范围限制操作 权限不足时友好提示

5. 接口设计

5.1 核心接口清单

🔗 接口规范说明

  • • 所有接口统一使用 RESTful 风格
  • • 请求/响应格式：JSON
  • • 认证方式：JWT Token
  • • 错误码统一规范：业务码 + HTTP状态码
接口模块 接口名称 请求方式 接口路径 说明
用户认证 用户登录 POST /api/auth/login 用户名密码登录，返回Token
获取用户信息 GET /api/auth/userinfo 根据Token获取用户基本信息
权限验证 GET /api/auth/permissions 获取用户权限列表
退出登录 POST /api/auth/logout Token失效处理
商户管理 商户列表查询 GET /api/merchants 支持分页、筛选、排序
商户详情 GET /api/merchants/{id} 获取商户详细信息
新增商户 POST /api/merchants 手动录入或地图添加商户
更新商户 PUT /api/merchants/{id} 更新商户信息
商户状态转化 POST /api/merchants/{id}/transform 目标→意向→正式商户转化
任务管理 任务列表查询 GET /api/tasks 支持状态筛选、分页查询
任务详情 GET /api/tasks/{id} 获取任务详细信息
领取商户任务 POST /api/tasks/claim 领取商户下所有任务
提交任务 POST /api/tasks/{id}/submit 提交任务处理结果
任务审核 POST /api/tasks/{id}/review 审核任务，通过或驳回
批量导入任务 POST /api/tasks/import Excel文件批量导入
地图服务 获取地图POI GET /api/map/pois 获取指定区域腾讯POI点位
正式商户地图展示 GET /api/map/merchants 获取正式商户坐标信息
POI数据导出 POST /api/map/export-pois 导出区域POI为Excel文件
地址解析 GET /api/map/geocode 地址转经纬度坐标

数据库查询 < 100ms 慢查询日志 复杂查询需优化
文件上传 < 10秒 实际测试 10MB以内文件
