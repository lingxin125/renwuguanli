# 商户地图官方能力核查

核查日期：2026-09-18。用于本轮地图任务管理 PRD 的技术可行性依据，未实施地图 SDK、未申请或调用业务 Key、未执行真实导航/定位验收。

## 结论与建议

高德 JS API 2.0 + Loca 2.0、腾讯 JavaScript API GL + 数据可视化库都能支撑“真实底图 + 商户点位 + 聚合 + 密度热力”的 H5 原型。2026-09-21 用户确认原型采用 **高德 JS API 2.0 + Loca 2.0**，只改移动端；商户、任务、交易标签、走访记录使用清楚标注的业务模拟数据。正式开发的地图平台由技术另行评估；该原型决定不代表已有可用 Key，也不锁定生产采购。腾讯能力记录仅保留为技术参考。

纯 HTML 可直接加载高德 JS API 并初始化地图，不需要更换框架。原型按一个商户、一个当前维护地址展示，不建立多门店模型。需验证地图容器高度、手机壳与弹层的尺寸更新、触摸操作及 Loca 图层兼容；定位需要安全环境和授权，导航唤起需真机核实。业务层本期不增加地址校正或目标放弃审批，任务审核沿用原流程。

地图平台提供底图、坐标展示和空间服务，**不会自动提供微邮付全部商户、任务、交易活跃状态、网点归属和走访结果**；这些内容由业务服务供给。地图点位颜色、任务徽标、意向标记属于产品及业务规则。地图 POI 搜索结果不可直接冒充平台目标商户。

HTML 手机壳仍为 H5，不等于微信原生小程序。正式小程序应单独验证原生 `map`、`MapContext`、`wx.getLocation`、`wx.openLocation`，不能假定 GL JS/Loca 代码可直接运行在原生组件中。

## 原型阶段与生产阶段的边界

1. **原型目标**：在 HTTPS/本地 HTTP 服务中接真实地图底图；展示模拟商户及其模拟任务/标签/走访状态；提供真实点选、缩放、聚合、热力切换和详情入口。顶部或说明区标注“业务数据为演示数据”。
2. **真实服务验证**：有合规可用 Key、域名配置和权限后，验证地图初始化、逆地理编码、人员定位及外部路线入口；未配置时显示明确的“地图服务未配置/暂不可用”，保留商户列表和详情，不以自绘地图冒充真实接口。
3. **模拟写操作**：领取任务、完成任务、标记意向、保存位置校正应明确为本地演示行为；正式版本通过服务端权限校验、并发控制、数据持久化、审计记录实现。
4. **主数据**：保存 source_coordinate_system、原始坐标、标准 GCJ-02 坐标、来源、采集/校正时间、精度、核实状态；未知坐标系不自动转换，已是 GCJ-02 的坐标不得重复转换。
5. **校正语义**：人员“刷新我的位置”只更新人员位置；商户“校正商户位置”是有权限的数据修改，需预览旧/新坐标、地址、原因和影响，确认并校验保存成功后才更新所有关联任务地图展示，不新增独立审批。
6. **热力口径**：热力按过滤后的去重商户集合计算；一个商户多个任务只记一个点和一个密度单位。无有效坐标商户不进入热力，但在总量中明确“未定位 X 户”，并提供补定位入口。
7. **合规与费用**：两家平台具体免费额度、商用授权、付费层、配额和域名策略取决于实际账号与当期规则，本次未登录控制台，不能承诺免费、无限量或免审批。上线前核实；原型文档不写入任何项目真实 Key。

## 后续接入验证清单

- JS API Key 产品类型、来源授权、白名单/安全配置、测试域名是否可用。
- 真机 HTTPS、浏览器定位权限、拒绝/超时/低精度场景。
- 同一 GCJ-02 坐标在地图、详情、导航目的地中是否一致，经纬度顺序是否正确。
- 地图密集点下聚合展开、同址多商户选择、缩放切换热力与标记是否符合 PRD。
- 密度为筛选后去重商户数而不是任务数，未定位统计可对账。
- 微信内置浏览器、系统浏览器、已安装/未安装地图 App 的导航与兜底。
- SDK 超时、配额/鉴权失败、无网时的错误态与业务列表可用性。
- 原生小程序另行验证热力图层接入、基础库、类目权限、隐私声明和商业条件。

本次依据官方文档验证“能力存在与主要接入约束”；未用官方示例 Key 或项目 Key 发起 SDK/API 调用，文档核查不等于运行验收。
